VisionInspect Technical Documentation

Exact API contracts, runtime lifecycle, domain mapping, and module architecture.

Overview & Architecture

VisionInspect is a production-grade visual inspection platform combining unsupervised anomaly detection (Anomalib/PatchCore) and supervised defect segmentation (YOLO26-seg) behind a single, learned-routing inference API

Core Architectural Decision: Anomalib's one-class models cannot identify out-of-domain samples. A lightweight YOLO26n-cls router determines input identity before specialist execution to prevent false-confident misroutes .
Request Lifecycle

Execution order for a single POST /predict call:

  1. Decode: Validates Content-Type: image/* and opens image using PIL. Returns 400 on failure.
  2. Route: YOLO26n-cls router classifies image into 18 categories with confidence metrics.
  3. Confidence Gate: If below VI_ROUTER_CONFIDENCE_THRESHOLD (default 0.6), stops execution and returns an UnrecognizedResult.
  4. Resolve: Lookup backend (anomalib or yolo26-seg) and checkpoint paths in model_registry.py. Missing paths or classes yield 500.
  5. Infer: Targeted backend runs inference using encapsulated pre/post-processing.
  6. Normalize: Formats output into unified PredictionResult.
image bytes -> decode -> route() -> [confident?] -> resolve() -> backend.predict() -> PredictionResult \-- no -> UnrecognizedResult (stop here)

Design Rationale
  • PatchCore Selection: High performance on small image counts (98.2% AUROC baseline across 15 categories).
  • ONNX Standard: Provides decoupling of PyTorch training setups from deployment environments.
  • Scoped Triton Usage: YOLO components leverage standard Triton servers while Anomalib remains in-process to avoid complex dynamic array post-processing on remote instances.
